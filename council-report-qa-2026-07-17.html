QA Council Report — Testing the Existing App

Hands-on audit of all 16 existing modules · fixes & amendments only, no new modules · 17 July 2026

The question: Test the existing Maridive Fleet Vessels app and recommend anything required or amended in the existing modules — without adding any module. Five advisors inspected the actual source code (screens, providers, services, models); the Executor also ran the test suite, analyzer, and risk-pattern greps. Every finding cites real files.

Chairman's Verdict

Headline defect (4 of 5 advisors independently): "offline-first" is not actually implemented. Hive persists only settings; every module writes straight to Supabase inside 26 silent catch (_) blocks with no retry queue. A tank reading or defect entered offshore shows on screen — then vanishes on restart.

Where the council agrees

  1. Data durability & integrity: offline writes lost; fetchAll() unordered/unpaginated (silently wrong tank levels past 1,000 rows); last-write-wins clobbering between two officers; REQ numbers that can duplicate (cache count + 1).
  2. Numbers not yet fully trustworthy: sounding tables are a linear fiction presented as authoritative; fleet fuel average counts unread tanks as 0%; certificate status lacks an "expired" tier and has a day-boundary off-by-one; pump calculator computes from zero when no reading exists.
  3. Daily-use safety gaps on every list screen: instant unrecoverable deletes with zero confirmations app-wide; Save buttons that silently no-op on invalid input; typed comments lost on rebuild; no search anywhere.
  4. Tests cover the wrong risk: all 11 are serialization round-trips; zero coverage of the alarm/expiry/average math crews act on.

Where the council clashes

Fix order: the Outsider says user-facing safety (deletes/saves/search) harms crews tomorrow; the Contrarian and three reviewers say the invisible data-layer bugs are graver — crews can't detect them and they harden as data grows. Resolved: data layer first, then the three worst UX traps.

The Expansionist's polish list (export coverage, cert dots on crew list, defect→requisition prefill, order-value totals, overdue chips) was unanimously judged right ideas, wrong time — don't surface more numbers before the numbers are trustworthy. Kept, sequenced last.

Blind spots the council caught

  1. Access control & audit trail (all 5 reviewers): no one checked Supabase RLS, role separation, or change history — any logged-in user can silently, permanently delete any vessel's quasi-legal records.
  2. One root cause: most data findings trace to a single primitive — CloudStore's whole-blob jsonb upsert. Fix the primitive once; six symptoms collapse into one repair.
  3. Nobody actually ran the app: no airplane-mode session, no two-device conflict test, no Arabic RTL runtime walkthrough.

The recommendation — a 4-phase repair sprint (existing modules only)

  1. Data durability: try/catch on every CloudStore put/remove + Hive pending-sync queue flushed on reconnect; ordered & paginated fetch; updated-at conflict guard; honest offline/auth error states replacing the 26 silent catches.
  2. Crew safety UX: shared confirm-delete + undo SnackBar; inline validation messages; onChanged draft persistence; search field on every list.
  3. Number honesty: sounding table labeled as estimate (or real calibration data); fleet averages skip unread tanks; "expired" certificate tier with date-only math; calculator guard.
  4. Tests + localization: clock-injected boundary tests; migrate the 35 hardcoded strings; full Arabic runtime pass.

Then the Expansionist's seven amendments. In parallel: review Supabase RLS and add change history to CloudStore.

The one thing to do first

Make one offline write survive. Wrap CloudStore.put in try/catch with a Hive pending-sync queue, then run the airplane-mode test: add a tank reading offline → kill the app → relaunch (reading still there) → reconnect (reading in Supabase). Everything else builds on that guarantee.

Full advisor findings

The Contrarian — data-layer failures (voted strongest, 4/5)

1. Offline-first is false. Optimistic in-memory update, then await store.put(...) with no catch, queue, or local persistence (tank_data_provider.dart:128-130); Hive holds only settings. Screens fire-and-forget (defect_list_screen.dart:427). Offline: record shows, put throws unhandled, record vanishes on restart — or sooner, since _loadAll replaces the whole cache on every token refresh.

2. fetchAll() unordered & unpaginated (cloud_store.dart:18). PostgREST caps at 1,000 rows; past that, an arbitrary 1,000 load and "current tank level = newest cached reading" is silently wrong — stale levels, false alarms.

3. Last-write-wins. put upserts the whole data blob, no version check, no realtime subscription. Two officers editing the same defect clobber each other invisibly.

4. REQ numbers collide. seq = cache count + 1 (tank_data_provider.dart:371-374): a delete or a second device produces duplicate REQ-xxx numbers on procurement documents. Microsecond IDs can also collide across devices.

5. Attachment fallback re-inlines base64 into jsonb on any upload error (attachment_store.dart:36-38) — multi-MB photos land inside record rows that then sync through the same failing path.

6. Every failure masquerades as wrong password. login's catch (_) => invalidCredentials (auth_provider.dart:72-74); 26 silent catches fleet-wide.

First Principles — can a mariner trust the numbers?

1. The sounding table is fiction (tank.dart:18-32): a linear 250cm profile invented from capacity ("good enough to demo"). Real tank geometry is nonlinear; sounding→m³ output is fabricated but presented as authoritative. Label as estimate or load real calibration data.

2. Offline-first false — UI shows in-memory cache, cloud is truth, disk holds nothing.

3. Unread tanks count as 0% in fleet averages (tank_data_provider.dart:133-139), dragging the fuel KPI down — though alert_thresholds.dart explicitly refuses that conflation elsewhere. Average only tanks with readings.

4. No "expired" certificate tier (vessel_certificate.dart:35-40): expired 6 months ago looks identical to 29-days-out; inDays truncation gives a day-30/31 off-by-one. Use date-only math.

5. REQ sequence collisions. 6. Pump calculator computes from 0 with no reading and clamps negatives, masking impossible operations (tank_calculator_screen.dart:98, 47-67).

7. All 11 tests are serialization round-trips — zero coverage of thresholds, averages, sounding math, sequence generation: precisely the numbers crews act on.

The Expansionist — 7 amendments, unanimously re-sequenced to last

1. Unified export covers 7 of ~13 modules (export_report_screen.dart) — certifications, maintenance, handover, logbook, urgent notifications missing though providers exist. 2. Crew list blind to certificates — one status dot + tap-through. 3. Defect→requisition one-tap prefill from requiredSpareParts (~15 lines). 4. Requisition value never totaled (unitPrice × quantity exist). 5. Overdue delivery invisible — one red chip. 6. Defect aging ("N days open"). 7. Overdue task counts exist but never shown on the fleet dashboard.

Council ruling: all seven stay on the roadmap — after the data layer, UX safety, and number-honesty phases. Reviewers' reason: "polish before integrity amplifies wrong numbers to inspectors — the worst audience."

The Outsider — daily-friction findings

1. Every delete is instant, silent, unrecoverable — 12+ screens, zero confirmations; the only AlertDialog in the app is the AI-review dialog; trash icons sit beside routine AppBar actions (daily_task_detail_screen.dart:26-32, port_call_detail_screen.dart:28-31); no undo SnackBar anywhere.

2. Save buttons silently no-op on invalid input — twelve screens share if (title.isEmpty) return;. Crew assume the app froze.

3. Typed text quietly lost — checklist comments commit only onSubmitted and controllers rebuild from stored state on every rebuild (daily_task_detail_screen.dart:72-80); same trap for defect "action taken".

4. No search or filter on any list (0 matches across 27 screens).

5. Sibling drift: sheets vs pushed screens; requisitions editable, defects not; defects get PDF, requisitions don't. 6. Locale leaks: hardcoded date formats, English enum names, 'pcs'.

Fixes: one shared confirm-delete helper, inline validation errors, onChanged persistence, a search field per list header.

The Executor — measured, with a verification plan

Ran: flutter test (11/11, all model serialization; zero widget/provider/service coverage), flutter analyze (clean), pub outdated (19 held back, none blocking). Greps: 26 silent catches, 31 DateTime.now() in models/state, 35 hardcoded English strings in screens, 0 force-unwraps.

This week: (1) wrap every CloudStore.put/remove, add Hive pending-sync queue, flush on reconnect — verify via airplane-mode test; (2) "cached/offline" banner instead of a silently empty-but-healthy fleet. Next: (3) clock-injected boundary tests for cert-expiry and task-overdue math; (4) migrate the 35 strings to ARB and re-verify in Arabic.

Peer-review highlights

What the anonymous cross-review surfaced

Strongest votes: Contrarian ×4 ("the bugs a crew can't detect and a developer can't fix later"; "failures that survive contact with production at scale"). Outsider ×1 ("the only response that watched a human use the app").

Blind-spot votes: Expansionist ×5 — unanimous. "Optimizes the roof while the foundation is condemned"; "an order-value stat computed from a truncated, unordered cache extends the lie with more confident-looking numbers."

What ALL five missed: (a) authorization & audit trail — Supabase RLS, role separation, change history; any account can permanently destroy quasi-legal maritime records; (b) the shared root cause — one CloudStore primitive (whole-blob jsonb upsert) behind most data findings: fix it once; (c) nobody ran the app — no airplane-mode, two-device, or Arabic RTL runtime session; (d) no migration/versioning story for the jsonb blobs.

Executor-reviewer's final priority: Contrarian fixes → Outsider items 1-3 → sync queue → number-honesty labels → Expansionist polish.
